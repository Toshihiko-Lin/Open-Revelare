# Film Dust Cleaner 可选组件接入评估

> 后续决定（2026-11-02）：取消外部组件与 LaMa 接入。相关实现草稿已撤回。改为升级内置 C# 手工除尘：多方向干净纹理选择、避开其他修复区、蒙版外边界颜色匹配及平滑羽化；不增加下载项或运行依赖。以下保留为历史评估。

评估日期：2026-11-02。结论：**可以以按需下载的独立处理组件接入，建议先做 CPU 版验证；当前版本不适合原样挂入渲染管线。**

本次仅评估，未改动产品代码。上游源码克隆至临时目录，审阅版本为 `130340ccd803238a1466554654e1f0b6e8430abd`（master）；`v1.5.0` 标签解引用为 `e003e124c1a548f83aa54bc09a9b0e420a7fe2cd`，两者不同，制作组件时必须固定实际审阅的提交及许可证，不能只标注标签。

## 1. 可复用的能力与实际入口

上游地址：<https://gitee.com/filmdust/film-dust-cleaner>。

- 自动灰尘候选：`analyze_image` → `detect_dust`，基于多尺度 DoG、Hessian、结构张量和边缘保护；无须 LaMa，也无须 PyTorch。
- 自动修复：`repair_image`，小点使用 Telea，较大区域尝试 Poisson 纹理合成。
- 手动划痕：`build_scratch_mask` → `repair_scratch`，沿引导线搜索划痕并生成软蒙版。
- 手动污点：`repair_spot`，LaMa 优先，缺少权重或失败时回退 OpenCV NS 与高频纹理。
- 保护区：函数支持保护蒙版及部分手动操作覆盖保护区。

上游是单文件 Python 程序，GUI 与算法在同一模块，可导入函数，但没有稳定的跨进程协议。现有 CLI 支持单张、批量、CPU/GPU 和蒙版导出，**只走自动检测与自动修复**；没有外部手动蒙版输入、划痕引导线输入、LaMa 引擎选择的参数。调用现有 CLI 不能覆盖全部功能，需要自行编写无界面的适配器。

## 2. 许可与下载边界

审阅提交的 `LICENSE` 是 MIT，`NOTICE` 列出了第三方依赖。代码接入本项目 GPL-3.0 管线的初步判断为可行，需保留版权、MIT 许可及相关第三方声明；修改部分记录来源和改动。制作二进制包时还须按实际打包的 Python、NumPy、OpenCV、Pillow、PyTorch 版本收集声明。

LaMa 项目代码采用 Apache-2.0：<https://github.com/advimman/lama/blob/main/LICENSE>。**不能由此推断下载权重已经获得相同授权。** 上游 `NOTICE` 明确要求在再分发权重前核查模型卡与许可；本次未完成 `okaris/simple-lama` 转换权重的完整授权链核验，权重自托管/再分发暂不纳入首版。

上游 `download_lama.py` 已实现双下载地址、临时文件、大小与 SHA-256 校验。目标是 TorchScript 文件 `big-lama.pt`，大小为 205,803,670 字节（约 206 MB / 196 MiB），不是 ONNX。可选下载只改变安装与分发方式，不能代替授权核验。

## 3. 与现有除尘管线的差异

本项目 `DustRemoval.cs` 当前使用手动圆形修复点和邻近纹理，`Pipeline.cs` 在畸变、LCC、暗角后、反相前调用；`RegionRender.cs` 支持局部渲染和上下文 halo。`ImageBuffer` 是 HWC RGB float32，数值本身不携带色彩含义。项目还要求不破坏源缓冲区、修复可保存、局部与整图渲染一致。

上游主要按归一化 `[0,1]` RGB 处理，没有与本项目工作空间、负片透射率或 HDR 数值的完整转换契约。函数输入形状兼容，不代表颜色和数值意义兼容。

必须处理以下差异：

1. **颜色与动态范围。** LCC 等操作后的数值可能超出 `[0,1]`。不能整图剪裁后回填。传统修复应验证可逆局部归一化，并由宿主保留蒙版外原始浮点值；LaMa 如在源负片域使用，需验证负片颜色、橙色片基与其输入分布是否匹配。直接反相处理再反算源域的路线也有损失风险，不能未经验证上线。
2. **蒙版不变性。** `telea8` 会先将整幅 RGB 转为 uint8，再返回浮点结果；因此对任意 float32 图像，自动修复会改动有效蒙版外的像素。`repair_spot` 最终整图 `clip`，超范围像素即使位于蒙版外也会改变。适配器返回结果后，由宿主按最终有效软蒙版合成，仅写入允许修改的像素。
3. **精度。** 16-bit 文件读写不等于 16-bit 修复精度。Telea/NS 的相关 16-bit 路径会将局部动态范围压缩至 8-bit 修复，再映射回来；需要检查色阶、色偏和颗粒。
4. **坐标与持久化。** 当前 `DustSpot` 圆点不能无损保存任意候选蒙版、保护区和划痕。需要源图坐标下的软蒙版/笔划、处理引擎、算法版本、参数与必要的缓存资产；随项目保存，并处理裁切、方向和局部解码偏移。
5. **局部渲染。** LaMa 对蒙版总包围框加 20 px 上下文，最长边超过 1024 会缩小处理再放大。多个远距离污点合并时可能损失细节。建议按相邻修复区域聚类，固定 ROI、padding 和缩放策略，缓存每个区域的修复补片，预览、放大与导出共享；不要逐显示瓦片独立推理。
6. **自动检测尺度。** 检测阈值、核与最大灰尘尺寸使用像素单位，低分辨率预览重新检测与全分辨率检测不会天然一致。预览只作候选探索；确认后的蒙版统一到源图坐标，避免导出时静默重新检测改变结果。

现有自动检测已停用，理由正是细节与灰尘难以可靠区分。建议新增“生成候选 → 查看、擦除、保护 → 确认修复”的明确操作，默认继续使用现有手动修复。

## 4. 推荐的可选下载方案

**基本安装保留现有除尘功能，新增独立下载的 CPU 增强组件。**

第一层：CPU 组件，包含固定版本 Python 运行时、NumPy、OpenCV 和 Pillow，以及固定上游提交与自有适配器。功能为候选检测、NS 污点修复与划痕修复。组件使用独立子进程，通过 JSON 请求元数据加二进制 float32 RGB/软蒙版交换；首版可用受控临时文件，成熟后评估共享内存。Tk GUI 无须分发。不要在用户机器运行安装脚本，也不要向系统 Python 执行 pip 安装。

第二层：可选 LaMa 扩展，额外提供权重及 PyTorch CPU 或 CUDA 运行时。权重约 206 MB，但总下载还包含运行时，不能宣传“下载 205 MB 即可”。实际包体积、内存、CPU 延迟和 GPU 显存须制作产物后实测。上游目前只有 CPU/CUDA 路线，不能据此承诺 DirectML、ROCm 或 Apple MPS 加速。

建议 Windows CPU 首发，随后分别构建并验证 macOS arm64/x64、Linux x64。已有 Deep-WB 的 ONNX Runtime 可作为未来统一推理方向，但不能直接加载 `.pt`；LaMa 转 ONNX 的算子支持、动态尺寸与结果一致性均未验证，应单独立项。

下载管理需要：用户明确点击下载、显示组件/模型许可与实际大小、固定版本与平台清单、SHA-256、取消/失败清理、校验后原子安装、可删除和离线导入。处理组件与模型存入用户数据目录，处理时不联网。任务异步运行，支持取消、超时和过期帧结果丢弃。

组件缺失时，原有手动修复仍可用。项目明确选择增强引擎后，导出不能静默切换为不同修复结果；应使用已保存的有效修复资产，或提示缺少指定组件，由用户决定如何处理。上游 LaMa 的静默回退需要改造成可观察的状态。

拟新增的职责边界（不是已存在 API）：`OptionalComponentManager` 管理安装；`IDustAnalysisBackend` 返回候选；`IDustRepairBackend` 返回局部补片与实际引擎。Core 保持独立，由 GUI/CLI 注入，避免让 Python 进程参与每次交互渲染。

## 5. 本次验证与限度

在临时 venv 中复用已有 NumPy 2.4.4 / Pillow，安装 OpenCV headless 4.10.0.84；未安装 PyTorch，未下载模型。上游未约束到该版本组合，此次结果只代表此组合。

- 上游 `test_scratch_repair` 通过：合成划痕吸附、8/16-bit 修复、保护区与坐标缩放；单次约 0.47 秒，仅是小合成样本。
- 上游 `test_spot_repair` 通过：NS、纹理、保护区、16-bit 与绝对蒙版；单次约 0.07 秒。
- CPU `analyze_image` + `detect_dust` 在 128×96 随机合成图上完成调用。这只验证入口可运行，不构成识别质量结论。
- 独立浮点不变性探针：96×128 RGB、4×4 输入蒙版、`grow=0`，上游仍对大于等于 12 px 的连通域自动扩一圈，最终有效蒙版为 32 px。以这个**最终有效蒙版**为准，8-bit 自动修复改动了全部 12,256 个蒙版外像素，最大绝对误差约 0.001961；16-bit 自动路径蒙版外 0 像素改变。
- 超范围探针：NS 污点修复把蒙版外 `[1.2, -0.01, 0.4]` 改为 `[1.0, 0.0, 0.4]`，确认直接接入会剪裁有效范围外的值。
- 当前提交未包含 README 和部分测试引用的 `sample/sample_positive.png`，因此没有执行完整上游套件，也没有伪造样本来宣称原套件通过。
- 没有验证 LaMa、CUDA、真实底片检测质量、24–100 MP 性能、ICC 端到端输出或跨平台安装。没有对现有产品代码作修改，因此没有运行本项目全套测试。

## 6. 落地顺序与放行条件

先验证 CPU 适配器的浮点传输、最终软蒙版回写、源图坐标及源缓冲区不变性；以真实底片、正片、文字、人脸、颗粒、细线和划痕样本评估误检。之后实现下载管理、项目资产和预览/导出共享缓存，再集成 UI。最后单独核验并接入 LaMa。

放行条件包括：关闭功能时行为不变；有效蒙版外浮点值逐位不变；裁切/旋转/局部预览与整图导出修复一致；项目重开可复现；缺组件有明确状态；坏下载可恢复；取消任务不污染下一帧；真实大图的内存与耗时在产品可接受范围内。

**建议批准的是“CPU 可选增强组件的验证与集成路线”；暂不将其原样作为默认自动除尘，也不承诺 LaMa 模型直接兼容现有 ONNX 后端。**
