# 标定实验

这个文件夹是 OpenRevelare 各项物理结论的**证据**。

README 说这个程序「物理可解释」、「每个参数都有明确的物理含义」——那么每一个这样的断言背后应该有一次可以被检验的计算，而不是一句口号。这些脚本就是那些计算。它们不是程序的一部分，也不参与构建；它们是当初做设计决策时的实验记录，留在这里是为了让别人能够检查、复算、或者推翻。

**其中有一个结论被推翻过**（见 `universal_crosstalk.py` → `paper_free_crosstalk.py`），并且两个脚本都保留着。这正是这个文件夹存在的意义:结论可以错，但错在哪、怎么发现的、后来怎么修正的，得留下痕迹。

## 依赖

多数脚本需要一份 [DiVERE](https://github.com/flipswitchingmonkey/DiVERE) 的 checkout 提供数据集(ColorChecker 实测密度、密度校正矩阵)。把路径作为第一个参数传入，或设环境变量 `DIVERE_ROOT`：

```bash
python3 docs/calibration/universal_crosstalk.py ~/src/DiVERE
```

`read_dng_matrix.py` 是纯标准库，不需要任何数据集。

## 脚本各自回答了什么

### 关于反相的数学

| 脚本 | 提出的问题 | 结论 |
|---|---|---|
| `grade_is_overloaded.py` | `grade` 到底在做什么，「相纸反差」是不是个恰当的名字？ | 不是。原先援引「C-41 低反差是为了印到高反差相纸上」来正当化 grade，这个说法经不起标准与代数两方面的检验——该参数实际同时承担了多件事。这直接导致了后来把自由度收敛到两端各三个绝对密度的重构 |
| `alignment_vs_chroma.py` | 把三个通道对齐(片基归黑、最亮处归白)能不能恢复色度？ | 不能，而且原因是结构性的。实测 Gold 200：让中性行尽可能中性，平均色度饱和度几乎不动(0.7237 → 0.7224，参考值 0.8056)。约 11% 的色度是逐通道操作**原理上**够不着的，必须靠跨通道变换。这也解释了为什么 DaVinci/Photoshop 那套手法「看起来够用」——它恢复了中性轴(最显眼的部分)，剩下的 11% 读起来只是「稍微平了点」 |
| `study_saturation.py` | (历史遗留)Cineon 逐通道反相会不会损失饱和度？ | 不会。**此脚本已不能运行**——它 import 的是 Python 原型的模块。保留作为证据，不作为工具 |

### 关于串扰矩阵：一次被推翻的结论

这两个脚本要按顺序读。

| 脚本 | 提出的问题 | 结论 |
|---|---|---|
| `universal_crosstalk.py` | 存在一个所有 C-41 胶片共享的通用串扰方向吗？ | **结论已撤回，勿单独引用。**整个设计押在这个前提上：程序有意不做逐卷标定，只有当串扰方向是 C-41 工艺的共同属性时这才站得住。但它用的每个 ColorChecker 数据集描述的都是 Kodak Endura Premier **相纸**上的密度，拟合出的矩阵映射的是「相纸→场景」，八种胶片的一致性有一部分来自共享的印片链路，而非胶片本身 |
| `paper_free_crosstalk.py` | 同一个问题，改用**无印片**的数据重问一遍 | 用 DiVERE 的密度校正矩阵(直接测负片，没有印片环节)重做，于是能做出之前做不了的交叉对比：**同一卷胶片换扫描仪**、**同一台扫描仪换胶片**。判据很干净——若矩阵按胶片聚类，那测到的是工艺常数;若按扫描仪聚类，那测到的只是仪器 |

### 关于输入色彩空间与绝对刻度

| 脚本 | 提出的问题 | 结论 |
|---|---|---|
| `solve_input_primaries.py` | 「输入基色 = sRGB」这个假设成立吗？ | 管线从不声明解码后的负片处在什么色彩空间。DiVERE 不用 chroma_grade，而是把输入基色**解出来**。此脚本拟合同一个量：接近则假设无害、chroma_grade 在修别的东西；相差远则固定 sRGB 就是问题所在 |
| `status_m_scale.py` | 窄带扫描能否让密度对上厂商发布的 Vision 3 数据？ | 问题要拆成三个，而它们**答案不同**。相机自己的 RGB 密度是一套私有刻度,与任何公开数据没有共享坐标。关键的反直觉结论：**对串扰矩阵而言厂商数据表没用**(该修正由传感器主导)，**对 gamma 而言数据表才是权威来源** |
| `gamut_check.py` | 那个「21% 色度缺口」有多少能用相纸色域解释？ | 约 6%，不是全部。也就是说色域差解释不掉大部分缺口 |

### 工具

| 脚本 | 用途 |
|---|---|
| `gen_fallback_table.py` | 从 rawspeed 的 `cameras.xml` 生成 `CameraMatrixFallback` 的表。内置 LibRaw(0.21.x)只认识 1181 台相机，列表停在若干现役机型之前。**难点在 key**——查表要对上 LibRaw **自己的** make/model 字符串 |
| `read_dng_matrix.py` | 读一个 DNG 的 `ColorMatrix2` 标签，打印可直接粘进 `CameraMatrixFallback` 的条目。后备表里的条目必须是**实测**的，这是测的方式。纯标准库 |

## 想加一个实验

照现有的格式：模块 docstring 里先写**提出的问题**，再写**判据**(什么结果算是支持、什么算是推翻)，最后写**结论**。先定判据再看结果——反过来做的话，任何数据都能讲出一个故事。

结论被后来的数据推翻了，**不要删脚本**，照 `universal_crosstalk.py` 的样子在开头注明并指向后续。
