# GUI 设计框架与优化顺序

## 1. 设计目标

用户在任意时刻应能直接知道：正在看哪一卷哪一帧、哪些帧被设为目标、当前操作会改什么、画面是否最终结果、工程是否已保存、出错后下一步是什么。

这是布局的约束，而不是另加一层冗长教程。现有“01 底片校准／02 成片调整”、明确分组同步、持久保存状态和任务恢复值得保留。

以下优先级为本次 GUI 工作的建议顺序：P1 表示先消除影响编辑范围或数据理解的歧义；P2 表示改善任务效率与一致性；不是对当前版本发布阻断级别或漏洞等级的判定。

## 2. 需要优先解决的具体问题

### D01 · P1 · 操作范围有四种不同回退规则

**代码事实：**本帧滑条忽略勾选；色彩勾选粘贴无目标不执行；构图／齿孔无勾选回退整卷；副本／移除无勾选回退本帧；整卷导出始终全卷。标定／成片“应用整卷”取实时当前帧，勾选粘贴取剪贴板。

**证据：**`MainViewModel.Sync.cs` 的 `Paste`、`Broadcast`、`ApplyGeometryToFrames`、`ApplyCropToFrames`、`ApplySprocketToFrames`；`MainViewModel.Roll.cs` 的 `StripTargets`、`ExportRollAsync`。

**体验假设：**同一勾选状态下相似的“同步”按钮会产生不同影响，用户需要记忆隐藏规则。

**建议：**所有批量动作先显示来源、目标范围、有效数量和字段摘要。工具旁直写“同步到所选 4 帧”或“同步到其余 35 帧”，无目标时不给含糊的“同步”。高频操作通过非模态摘要直接执行并可撤销，避免每次增加确认框。显式目标选择是后续可选的行为调整，须同时修改命令契约。

**验收：**勾选含当前帧、只勾当前帧、空勾选时，执行前显示的数量与真实写入对象完全一致；用户无需读 tooltip 即可判断范围。

### D02 · P1 · “重置本帧调整”跨越多个编辑阶段

**代码事实：**重置不跟随面板，触及标定、成片、镜头、齿孔和几何；还清除扫描分格 `SplitCell`。也不是所有编辑都清空。

**证据：**`MainWindow.axaml.cs:2840`、`MainViewModel.cs:4436`。

**体验假设：**在成片标签点击重置，可能丢掉用户不打算动的标定与分格依据；名字未交代这种范围。

**建议：**分为“重置成片调整”“重置本帧标定”“重置构图”“清除修复”，保留明确的“重置本帧多项参数…”入口，展示精确范围。导入分格应作为帧结构边界保留，是否允许解除分格应另有语义。此项需要行为层实现，不只是改标题。

**验收：**成片重置不改变已确认的标定、扫描分格与修复点；其他重置按定义影响字段；一键撤销恢复完整状态。

### D03 · P1 · 卷级与帧级设置混在同一个检查器

**代码事实：**底片页大多数端点控件修改当前帧，黑白模式与 LCC 启用为卷级；底部空间／HDR／LUT 有卷级渲染含义。已有整卷同步摘要，但范围仍不在所有控件旁一致呈现。

**证据：**`MainWindow.axaml`、`MainViewModel.Roll.cs` 的 `Monochrome`、`OutputSpaceIndex`、`HdrEnabled`；`MainViewModel.cs:934` 的 `OnLccEnabledChanged`。

**建议：**检查器顶部固定当前帧身份；卷级设定归入独立“本卷设置”，或在现有位置标注整卷范围。保留“底片校准／成片调整”自然语言主标题，Cineon／Display／Stage 1/2 降为可查技术名。禁止给一个含卷级例外的面板笼统加“全部仅作用本帧”。

**验收：**用户能区分修改当前帧端点与切换黑白／LCC／HDR的范围；切换帧后不会误以为卷级设置属于刚选中的帧。

### D04 · P2 · 渲染空间与文件交付的位置关系仍易误读

**代码事实：**输出选择已有“整卷渲染空间”名称和说明；修改空间会改变渲染，导出继承，不自动转 sRGB。底部空间／LUT／HDR 紧邻导出。

**证据：**`MainWindow.axaml:848` 起，`Models/ExportOptions.cs`，`MainViewModel.Roll.cs` 的 `OutputSpaceIndex`。

**建议：**视觉上分为“本卷渲染”和“交付”。导出汇总明确来源空间、SDR/HDR、容器和是否包含成片调整。后续可增加分享／后期／中间文件用途入口，但不能把 P3 卷静默改成 sRGB，或给尚未实现的派生渲染承诺同观感。

**验收：**同一卷导出 JPEG 和 TIFF，用户能说明哪些只是文件选项、哪些会改变工程画面；HDR 基底空间与卷渲染空间不混淆。

### D05 · P2 · 同名“导出印样”具有两种来源

**代码事实：**图库导出复制缓存 JPEG 封面；修片导出重新生成，具有版式、尺寸和 HDR 选择。前者不是后者的快捷版。

**证据：**`LibraryView.axaml.cs` 的 `OnExportSheetClick`；`MainWindow.axaml.cs` 的 `OnContactSheetClick`。

**建议：**图库改成“保存封面印样副本”，并能看出生成状态；修片保留“制作／导出整卷印样”。不强制图库操作解码整卷。

**验收：**用户执行前知道拿到的是已存封面还是新渲染，缓存缺失时有明确下一步。

### D06 · P2 · 不同窗口的提交时机不一致

**代码事实：**同步项实时生效，关闭不回滚；印样直接绑定卷信息且样式等立即写入设置，不导出也会保留修改；偏好通过保存提交多数项，主题／语言先预览，取消按钮恢复。

**证据：**`SyncDialog.axaml`、`ContactSheetDialog.axaml.cs` 的构造和 `OnStyleChanged`、主窗口印样调用；`PreferencesDialog.axaml.cs` 的保存／取消处理。

**建议：**实时编辑窗口明确“更改自动保存”，底部使用“关闭”；草稿窗口统一保存／取消，所有退出方式都遵守同一规则。不要让“取消导出”被理解为撤销卷信息。

**验收：**关闭按钮、Esc、标题栏关闭和取消文件选择器对数据的影响都有定义，且与界面文案一致。

### D07 · P2 · 裁切提示的关闭会带走提交按钮

**代码事实：**关闭提示条同时隐藏应用／取消，只剩 Enter／Esc。代码虽恢复焦点，鼠标提交入口不再常驻。

**证据：**`MainWindow.axaml.cs` 的 `ApplyBannerVisibility`、`OnBannerCloseClick`。

**建议：**工具提示可关闭，裁切事务动作常驻工具栏；退出工具等于取消或明确询问，行为一致。避免在原生预览上方依赖不可覆盖的浮层。

**验收：**关闭说明后，仅用鼠标仍能提交和取消裁切；切帧不会把旧草稿应用到新帧。

### D08 · P2 · 偏好标题栏关闭的预览回滚需补测

**代码事实：**取消按钮调用 `App.ApplyTheme()` 和 `Loc.Apply()`；读取整份偏好窗口代码未见与窗口关闭配对的同等恢复处理。

**证据：**`PreferencesDialog.axaml.cs` 的 `Build`、`Persist`；`cancel.Click` 回调。

**推导风险：**改主题／语言后直接点标题栏关闭，可能留下未保存的预览状态。这里尚未运行重现，不当作已实测缺陷。

**建议：**统一窗口结果与退出收尾，保存完成标记决定是否回滚预览。

**验收：**取消、Esc、标题栏关闭都恢复旧语言／主题且不保存其他草稿；保存后重开一致。

### D09 · P2 · 双份菜单的功能覆盖已有漂移

**代码事实：**主窗口 Help 有“打开 LUT 文件夹”，当前 `BuildWindowMenu` 原生 Help 列表没有对应项，macOS 又隐藏窗口菜单。复用处理器只能避免处理逻辑漂移，不能保证两份入口清单相同。

**证据：**`MainWindow.axaml` 的 Help；`MainWindow.NativeMenu.cs` 的 `SetUpNativeMenu`、`BuildWindowMenu`。

**建议：**统一命令目录生成两种菜单，仅把平台差异作为布局配置；为原生入口覆盖做轻量检查。

**验收：**三平台都能访问产品承诺的 LUT 管理入口；应用菜单内关于／偏好等合理差异保留。

### D10 · P2 · 旧术语和指导残留

**代码事实：**界面已用“01 底片校准／02 成片调整”，但复制菜单、文档与 tooltip 仍有 Cineon／Display／Stage 等不同命名；导入自动分析 tooltip 仍描述 `T_base → 白平衡 → D-max → 黑白场`，模型注释还描述已移除的导入选择。

**证据：**`ImportDialog.axaml` 的 `AutoInvertChk`；`Models/ImportConfig.cs`；`GUIDE.md` 与当前 XAML。

**建议：**建立术语主表，主界面统一自然语言名称，技术名称在详情中映射。对文档、提示、快捷键帮助、中文英文和原生菜单一起检查。

**验收：**用户按文档能找到同名入口；不再要求操作已不存在的导入步骤，也不把场景高光代理称作实测 D-max。

### D11 · P2 · 窄窗口把看图与调参分到上下两屏

**代码事实：**小于 1100 宽时，预览固定到约 340–520 高，检查器 620 高，二者通过外层滚动连接；原三栏不再同屏。

**证据：**`MainWindow.Responsive.cs`。

**体验假设：**在小屏幕和较高缩放下，用户可能滚到滑条时看不到画面，失去调节反馈。没有实际运行，所以不能断言某个 DPI 必然溢出。

**建议：**比较“可收起胶片栏＋侧检查器”“固定预览＋可滚参数”“检查器抽屉”三种低保真方案。优先验证预览与当前调参是否同时可见，而不是直接选某个固定断点。

**验收：**800×520、1024×768、1280×800 和常见 DPI 下能完成采样、曝光与裁切；按钮不出屏，不出现相互争夺滚轮的滚动区。

### D12 · P2 · 结果清单已具备数据，阅读方式可优化

**代码事实：**导出报告已有逐项状态、汇总、目录和重试，但通过通用 InfoDialog 展示拼接长文本。依赖窗口同样主要为长文本。

**证据：**`MainWindow.axaml.cs` 的 `ShowBatchExportReportAsync`；`ProjectDependenciesDialog.cs`。

**建议：**保留复制文本能力，增加失败／未执行优先的结构化结果，文件名、原因、路径与操作固定对应。归档依赖也按原片／参考／LUT 分组，并区分存在与有效。

**验收：**36 帧中某帧故障，用户可快速定位、复制错误、修复和重试，无需读完所有成功路径。

### D13 · P1 · 卷信息不同入口存在字段丢失路径

**代码事实：**印样可填写 `FilmIso` 与 `DevProcess`；图库卷信息窗口没有这两个输入。`RollInfoDialog.Collect()` 新建 `RollNotes` 时未保留它们，随后 `LibraryViewModel.SaveNotes()` 会把返回对象中的空值写回当前卷或工程。

**证据：**`RollInfoDialog.axaml.cs` 的构造和 `Collect`，`LibraryViewModel.cs:480` 的 `SaveNotes`，`ContactSheetDialog.axaml` 的 ISO/EI 与工艺输入。

**源码推导：**先在印样填 ISO/EI 和工艺，再从图库卷信息修改相机并保存，会清空未在该窗口展示的两项。调用链已经核对；尚未启动 GUI 重现。

**建议：**所有入口对同一对象使用保留未编辑字段的草稿／补丁语义，或共享完整编辑器；不能用局部表单重新构造对象覆盖所有字段。此项优先于视觉重排。

**验收：**从任一入口编辑一个字段后，其余已填字段全部保留；同时测试当前打开卷与未打开卷两个保存分支。

## 3. 建议的信息架构

这是一套目标框架，尚未实现，不主张把流程全部改成强制逐步向导。

### 全局层：应用与工程

菜单负责低频文件操作、偏好与帮助；工作区切换负责图库／修片；持续显示当前工程身份与保存状态。错误恢复入口不依赖某张预览成功显示。

### 图库层：找到卷、知道卷是否可用

保留卷墙与分面；突出卷名、有效帧数、工程可用性。低频管理进入明确菜单，工程删除与移出索引分组。空图库、筛选无结果、工程缺失、封面尚未生成分别设计。

### 修片层：图像居中，参数与操作有明确边界

- 卷／帧上下文：卷名、当前帧编号及名称、勾选数量和清除入口。
- 预览工具：查看模式、缩放、构图工具和当前活动工具状态。
- 底片校准：代表帧参数、证据、单帧／整卷分析；本卷光学／输入设置有清晰范围标记。
- 成片调整：白平衡、基本、影调、曲线，保留专业控制。
- 构图与修复：裁切／方向／拉直／修复／齿孔，能持续看到图像。
- 本卷渲染：空间、LUT、SDR/HDR、上限，独立于导出动作分区。
- 批量动作：按当前任务显示来源／目标／分组摘要，不散落多套无区别图标。
- 底部反馈：保存、显式任务、可恢复警告三类独立信息；诊断详情按需打开。

### 交付层：看清将写出什么

先确定当前帧／所选帧（若实现）／整卷／印样，再选格式与用途。最终确认显示真实文件性质、数量、输出名示例和覆盖策略。结果中心沿用已有任务状态，不另造第二份导出事实来源。

## 4. 通用组件与命令契约

### C01 帧上下文

参数：卷、当前帧、当前帧序号、有效勾选数、正在使用的目标范围。当前帧和勾选集合分别表达，不能只用同一种边框颜色。虚拟副本与扫描分格需能辨认。

### C02 批量动作摘要

参数：操作 ID、来源类型（当前实时／剪贴板）、源帧、目标 IDs、有效数量、字段组、是否可撤销。摘要和执行必须读取同一份目标解析结果，避免显示 5 帧、提交 4 帧。

### C03 参数行

包含自然语言标签、真实单位、数值、范围、复位、已修改反馈、键盘焦点。技术参数可保留原名，但需要一行可理解解释。禁止把当前默认值当作适合所有底片的推荐值。

### C04 工具状态与事务

包含活动工具、来源图像版本、草稿、提交／取消、指针捕获。提示文案与事务按钮分离；换帧、切模式、任务开始、窗口失焦都要定义收尾。

### C05 校准证据

显示来源、作用帧范围、适用修订、置信度及风险。手动修改后改为“旧统计不再适用”；区分实测／推断／代理，不用一个绿色勾代表全部。

### C06 状态与恢复

工程保存持久状态、任务运行状态、资源阻断、预览暂态相互独立。每个错误至少提供原因、受影响对象和可执行下一步；技术详情可展开或复制。

### C07 输出摘要

格式／编码／位深、色彩空间／基底、SDR/HDR、是否包含成片调整、尺寸、锐化、元数据、目标数量与冲突策略由最终有效配置生成，不能只复述用户原始勾选。

### C08 命令目录

概念字段：`id / label / category / source / resolveTargets / canExecute / disabledReason / execute / undoPolicy / shortcut / platformPlacement`。这是建议契约，不要求一次引入新框架。

先为 D01 的几种命令建立共享目标解析和摘要，再扩至菜单。不要先大规模搬动 MainViewModel 的 partial 文件，也不要新增另一套脱离现有事务、任务和保存协调器的可变状态。

## 5. 布局原则

1. 预览是主要工作区域，当前活动参数与预览应尽量同时可见。
2. 高频直接操作保留可见入口；低频工程、支持和技术细节渐进展开。
3. 折叠组是降低信息量，不能隐藏当前操作的重要前置条件或活动错误。
4. 图标按钮具备可访问名称、焦点和 tooltip；范围不能仅用广播图标表达。
5. 中文英文、长文件名、长路径、DPI 与原生菜单一起设计，不仅验一张默认尺寸截图。
6. 现有原生预览有叠层限制；通知与工具动作放在可可靠点击的壳层区域。
7. 保留专业能力可达性；减少默认需要理解的决策，而不是删除必要参数。

## 6. 分阶段实施

### R1：语义收敛

优先修复 D13 的跨入口字段覆盖，再做术语主表、目标解析、动态范围文字、来源／分组摘要、重置拆分设计；核对菜单平台覆盖与窗口提交语义。交付是可运行的小范围行为改进和相应验收，不是全窗口换皮。

### R2：主工作区低保真与任务测试

用既有功能做主窗口和窄屏方案，完成导入、代表帧标定、部分同步、裁切、单张／整卷导出五条任务。记录用户的误操作与求助点，再定布局。

### R3：窗口与反馈统一

统一导入／导出／印样／偏好的动作位置、提交语义、键盘交互、错误布局；把任务与依赖长文本升级为可定位的结构化结果。保留报告复制能力。

### R4：视觉与跨平台收尾

统一间距、文字层级、控件密度、图标、焦点、浅深主题；检查 Windows 原生预览、macOS 原生菜单、Linux SDR 回退。不改算法语义来适应视觉稿。

## 7. 明确不在这次文档中承诺的能力

尚未实现的建议包括：统一批量目标选择器、导出所选帧、分享派生渲染、拆分重置、结构化任务中心以及新窄窗布局。它们是待排期设计项，不能写进现有用户操作指南当成可用功能。
