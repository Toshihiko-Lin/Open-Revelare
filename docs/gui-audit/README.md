# GUI 功能与交互审计：设计基线

日期：2026-11-01。对象：当前工作区的 OpenRevelare 桌面 GUI。目标：先完整理解产品，再建立可以指导 GUI 重构的功能、对象、作用范围、流程和状态框架。

后续实施已开始：[本轮打磨与证据](05-polish-progress.md)、[实际界面总览](ui-review.html)、[可复现渲染工具](preview/README.md)。下文的“未修改 GUI”与 387 条计数是最初静态审计的历史基线；当前源码索引以重建后的 JSON 为准，实施完成度以进展文件为准。

这份审计将**现状、从代码推导的体验风险、建议设计、待实测项目**分开记录。没有修改 GUI 或处理算法。

本版整理了 14 个功能域、20 组操作契约、9 条完整流程、13 项设计／行为问题与 16 个验收场景。静态索引记录 10 个 XAML 文件中的 387 个控件／输入表面声明，另附 103 条动态界面与事件接线候选；这些数值不代表同屏按钮数或完整运行时实例数。

## 如何使用这套框架

先按用户任务检查功能是否完整，再按操作契约检查是否可理解，最后讨论空间分配、密度、图标和样式。一个按钮移动后，仍要能回答：对谁操作、改什么、什么时候完成、如何恢复。

建议后续每项 GUI 变更都关联功能编号、操作编号和验收场景。不要用截图的观感作为唯一验收依据，也不要把同一功能的多个入口误算成多个功能。

## 取证方式与边界

- 静态读取 `Views`、`Controls`、`ViewModels`、`Models`、关键服务与 Core 导出策略；控件源清单覆盖 `Views/*.axaml` 和 `Controls/*.axaml`。
- 追踪主窗口事件到 VM 方法，重点核对同步、导出、结构编辑、撤销、保存和错误恢复。
- 对照离线 `FIRST-ROLL.md`、`GUIDE.md`、2026-10-17 产品评审。文档、注释和实际调用冲突时，以实际调用为准，并保留差异。
- 查看仓库已有图库和校准截图，作为视觉历史资料；截图与当前 XAML 已存在差异，不能代表当前运行态。
- 这次没有启动桌面应用，没有进行真实 RAW/TIFF、HDR 显示器、辅助技术或三平台端到端测试。以下“已确认”均指源码可以确认的行为；易用性结论是待用户任务测试的设计假设。
- C# 动态构造控件另列定位候选，不能把候选数理解为完整运行时控件数。操作系统文件选择器、Avalonia 模板、重复缩略图实例不计入声明数。
- 工作区原有 `packaging/ci/heic-smoke.py`、`packaging/heif/bridge.cpp`、`packaging/heif/hardware-macos.cpp` 修改未改动；基线 HEAD 和被扫描界面文件的摘要见 JSON。

## 更新方法

在仓库根目录运行：

```powershell
python docs/gui-audit/build_inventory.py
```

脚本仅使用 Python 标准库，重新生成两份控件索引。它不会自动更新人工分析中的事实、优先级和设计建议；行为改变后必须重新追踪相应方法。行号是本次快照的位置，重构后以方法名和新清单定位。

## 当前核心判断

当前产品已经具备从导入、反转、精调到交付和可恢复归档的完整链条。GUI 优化的首要目标是让“**当前帧、勾选集合、整卷、导出任务、应用偏好**”这五种范围始终可辨认，并把“处理参数、查看状态、文件交付”三类操作区分清楚。

现有自动保存状态、批量结果与续跑、依赖清单、工程归档、结构操作撤销都已有实现。后续设计应利用这些能力，避免沿用旧评审中“缺失这些能力”的结论。

另外发现一条应先处理的数据完整性路径：图库卷信息表单未展示的 ISO/EI 与冲洗工艺，在保存其他字段时会被空值覆盖，见 D13。该结论来自完整调用链核对，尚未运行 GUI 重现。
