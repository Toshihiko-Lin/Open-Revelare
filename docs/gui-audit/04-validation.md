# 验收与覆盖清单

## 1. 当前审计交付的验证

这次验证对象是文档和静态索引，不是 GUI 新功能。没有修改生产代码，没有宣称执行完整 .NET 测试或桌面端到端测试。

索引应能重建、JSON 可解析、所有记录的文件／行号存在、XAML 记录能定位到相应元素、事件方法可以追踪。提交前检查文档本地链接、差异范围、原有工作区文件不受改动。计数以重建后的 JSON 为准，不把源码声明数当成按钮或功能总数。

本次实际结果：387 条 XAML 声明位置全部核对通过；所有被扫描界面源文件的 SHA-256 与清单一致；XAML 事件处理器在对应代码后置／partial 类中均可找到；6 份 Markdown 的本地链接全部有效。`git diff --check` 通过。未执行 GUI 行为测试。

## 2. 材料基线

准备可公开或本地授权使用的样本，并给每组保存输入、预期范围与截图；不要在报告中复制私人原片路径或 EXIF。

- 同一卷普通 RAW，含可靠裸片基、高光丰富／缺失、局部灰尘、不同方向。
- TIFF 嵌有效 ICC、可信标签、无声明、明确线性、浮点等不同分支。
- 一文件多格扫描、识别错误、横竖条、分格和虚拟副本组合。
- 黑白负片；黑白叠彩色印片 LUT 的预期染色。
- 有效／缺失／内容变化的 Path A、LCC、外部 LUT，含不同输入族参考。
- 重复文件名、中文长路径、同名不同内容、源目录不可写。
- 存在部分成功结果的旧批量任务与变更后的工程。
- 旧管线工程、相对路径工程、完整归档。

HDR 和三平台验收需要明确设备、OS、查看器版本与输出路线；当前审计没有这些实测数据。

## 3. 任务级验收脚本

### T01 · 第一卷成功交付 · F03/F07/F08/F11/F13 · W01

不看长文档，导入普通 RAW 卷，等待标定完成，调一帧，导一张，再导整卷并重开工程。记录首个可用预览、分析完成、首张成功交付的时间，以及误把临时图当最终图的次数。先建立基线，不凭空设置“必须 30 秒”的性能门槛。

通过标准：用户能识别分析是否完成；文件与工程都可重开；标定、曝光、裁切和帧顺序与保存前一致。

### T02 · 当前帧与勾选集合 · A01–A10 · D01

使用 8 帧，当前帧设为第 2 帧。分别测试空勾选、只勾当前帧、勾第 2/3/4 帧、只勾第 3/4 帧。每种情况执行本帧调参、本帧粘贴、勾选粘贴、整卷应用、几何同步、创建副本和整卷导出。

通过标准：界面显示的实际目标与契约一致，非目标保持原参数，来源“实时当前／内部剪贴板”可判断；撤销恢复全部目标。优化前先记录当前规则，优化后按明确批准的新契约验收。

### T03 · 批量事务失败 · F05/F07/F08 · A06–A08

勾选若干帧，令其中一张源不可用后同步。

通过标准：参数批量准备失败不部分写入；目标选择保留供修复后重试，错误指向问题文件。修复后一次应用、一次撤销。

### T04 · 重置范围 · A20 · D02

扫描分割帧先做标定、成片、方向裁切、修复，再创建虚拟副本。分别测试当前版本重置实际影响与未来拆分重置的定义。

通过标准：按钮名称与写入字段一致；尤其分格是否解除必须显式定义；一次撤销恢复分格／构图与参数。不能只检查曝光归零就宣称通过。

### T05 · 采样与相互覆盖 · A11–A15

依次做片基、高光、灰卡、智能推断、成片中性采样，记录每一步的端点与成片白平衡。

通过标准：区分底片标定与场景白平衡；同组端点被覆盖时反馈可理解；人工修改后不继续展示旧统计为当前置信度；黑白模式隐藏项正确。

### T06 · 裁切工具生命周期 · A16–A19 · D07

进入裁切、修改草稿、隐藏提示、用鼠标提交／取消；测试 Esc／Enter、切帧、切工具、失焦、原生预览切换。修复笔从预览拖到窗口外松手。

通过标准：不会把上一帧草稿写给下一帧；取消不改存储裁切；交互预览不永久卡在低清；隐藏说明后仍有可用提交路径。

### T07 · 文件格式与渲染语义 · F10/F11/F12 · W05

分别在 SDR 与 HDR 卷测试 JPEG、HEIC、TIFF、DNG、场景线性 TIFF，检查最终摘要、位深／编码、ICC／色彩标签、尺寸、元数据、锐化适用条件。

通过标准：文件类型与摘要吻合；继承空间与增益图基底含义不混淆；场景线性没有成片调整，DNG 不被等同为同一种场景线性母版；关闭不适用项不留下误导性勾选。

文件兼容性以目标应用实际打开为准；不将 HEIC 编码器存在当成所有系统均支持 HDR 显示的证据。

### T08 · 批量导出恢复 · F11/F13 · W06

36 帧任务中让中间一帧失败，测试继续／系统性失败、用户取消、关闭重开、重试；再修改工程、参考或已完成输出，测试恢复阻断。

通过标准：完成／失败／跳过／未执行数量准确；已完成不重复写入；重试使用冻结参数；依据变化时说明为何必须新建任务。

### T09 · 自动保存与关闭失败 · F13 · W07

编辑后立即关闭，制造不可写／磁盘错误并分别选择重试、恢复副本、继续编辑、明确放弃。测试切卷和关闭时仍有在途任务。

通过标准：保存失败时工作仍可恢复，窗口不提前销毁；独立保存状态不被普通预览消息覆盖；取消恢复文件选择器不等于丢弃。

### T10 · 归档与依赖恢复 · F13 · W07

生成依赖清单；将完整归档移动到新目录重开；缺失一个参考、提供同名不同内容候选、在拷贝中修改资源。

通过标准：清单导出不被误认为资源复制；归档可复算；存在／有效区分明确；无效候选不覆盖原声明；取消或失败不发布半成品。

### T11 · 卷与帧删除 · F02/F05 · W09

真实帧含多个副本时移除、撤销；仅移除副本；尝试移除最后一帧。分别从图库移出索引和删除工程。

通过标准：连带数量正确，结构撤销保留之前编辑历史；最后一帧有明确限制；图库删除不会暗示能用帧撤销恢复。

### T12 · 对话框退出语义 · F12/F14 · D06/D08

印样修改信息／样式后关闭；偏好更改主题／语言后分别保存、取消、Esc、标题栏关闭；导出选项确认后取消位置选择；同步项改变后关闭。

通过标准：每条退出路径的持久化结果都与文案相符；语言切换后保留尚未保存的其他选择；当前偏好标题栏关闭风险需给出运行结果，不能靠代码猜测记为通过。

### T13 · 菜单、键盘与辅助操作 · F01/F14 · D09/D10

核对 Windows/Linux 菜单与 macOS 原生菜单，包括 LUT 文件夹和技术报告。全键盘完成打开、切帧、编辑、裁切、导出；在 TextBox、数字输入、下拉和曲线上测试快捷键冲突。

通过标准：图标有可访问名称；焦点可见且顺序合理；文字复制不触发参数复制；关闭说明不丢失操作焦点；菜单提示与实际键位一致。

### T14 · 响应布局、长文与原生叠层 · F01/F06 · D11

检查 800×520、1024×768、1280×800、1920×1080；100%／150%／200% 缩放；中英文、长文件名与长错误路径，多个通知并存。

通过标准：当前参数操作与图像反馈可关联，主动作和错误恢复可达；原生预览不吞掉通知和按钮；滚动不造成用户误调滑条。

### T15 · 印样来源与元数据 · F12 · D05

修改一帧后分别从图库保存缓存印样、从修片重新制作；开启 HDR 印样；填写胶片与数字化两类元数据。

通过标准：用户知道封面缓存与新渲染的区别；SDR 预览不承诺 HDR 高光观感；胶片曝光不会被翻拍曝光悄悄填入；印样烧字不被称作 EXIF。

### T16 · 跨入口卷信息完整性 · F12 · D13

在印样填写 ISO/EI 与冲洗工艺，再返回图库“卷信息”只修改相机。分别对当前打开卷和未打开卷保存，然后重开印样及工程。

通过标准：ISO/EI、工艺和其他未编辑字段均保留；本次源码已发现覆盖空值路径，需在修复时补针对对象 round-trip 的回归验证。

## 4. 建议用户任务测试

先邀请少量目标用户分别覆盖初次使用和有胶片数字化经验的人。给任务和素材，不给按钮顺序。观察完成率、范围判断错误、误覆盖、撤销使用、求助次数，以及失败后的恢复时间。

用户频率、平均耗时、满意度和“最常用按钮”目前均没有实测。应先观察再决定是否收起高级工具、改变默认值或引入强制向导。

## 5. 未来版本的覆盖维护

新增或删除控件后重建索引；行为变化更新 A 操作契约；新增任务更新 W 流程；设计项实施后标记 D 状态并链接变更；最后记录 T 验收证据和平台环境。

禁止只写“已测试”而没有说明是源码核对、单元测试、运行态操作、真实文件验证还是目标用户测试。这五种证据不能互相替代。
