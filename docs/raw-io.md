# RAW / TIFF 原片的性能与色彩检查

一般翻拍只有相机 RAW，扫描只有 TIFF / FFF。本实现不要求额外光源数据或色卡，
也不把画面中某块区域假定为中性灰。没有外部参考时，报告验证的是文件证据和内部一致性，
不能给出绝对色准、胶片型号或光源光谱的结论。

## 源数据复用

RAW 的顺序读取结果进入最多 256 MiB、16 项的内存缓存。缓存键包含规范路径、长度、
修改时间和创建时间；同一版本的并发读取合并为一次。缓存只保留不可变文件字节，
每个解码仍使用独立 LibRaw 上下文，半尺寸、FBDD、区域和后端设置不会混用解码结果。
它省去重复磁盘读取和大数组分配，不会省去 LibRaw 解包本身。

内存预算跟随可用内存与进程/容器上限收缩，读取时淘汰旧项；切换或清空卷时释放缓存。
文件过大或内存不足时照常读取但不保留。正在解码的上下文继续持有自己的输入，
清缓存不会让原生指针失效。保持所有文件属性不变的原地改写不在版本键的检测范围内。

TIFF / FFF 的多裁切共享扫描行已用于印样、导入/重开后的预热和整卷分析。
同来源每批最多四个预览，按全部输出计算内存预算。批处理失败时逐个裁切重试，
一个坏裁切不会取消其他裁切的分析资格；统计结果仍按卷内顺序归并。

## 原生构建

默认维持可分发 CPU 指令集、精确数学、关闭 OpenMP 和 IPO。IPO 在本机的单个线性
DNG 对照中未显示稳定收益，因此保留为对照开关，不默认启用，也不宣称所有相机格式提速。

```powershell
./packaging/libraw/build-windows.ps1
# 对照构建，比较同一批原片的阶段耗时与像素散列：
./packaging/libraw/build-windows.ps1 -EnableIpo
```

Unix 使用 `OR_RAW_ENABLE_IPO=ON ./packaging/libraw/build-unix.sh`。
OpenMP 的独立开关为 Windows 的 `-EnableOpenMp` 或 Unix 的 `OR_RAW_ENABLE_OPENMP=ON`；
启用者需部署相应 OpenMP 运行库，并测量文件间并发与文件内线程的组合，避免过量线程。
默认构建仍不增加这项部署依赖。构建来源、IPO/OpenMP 状态写入诊断，未开启 fast-math。

## 原片色彩证据

RAW 的线性相机原生通道现在明确标为 `LinearInCaptureChannels`，其原色仍未表征，
不会因为进入兼容工作域就被声明为已转换的 ACEScg。相机矩阵不会自动放进负片密度计算。
TIFF 继续优先使用有效内嵌 ICC，其次读取文件自身的色度、白点和曲线声明；缺少这些信息
时，报告明确记录推定依据，而不从负片直方图猜测 gamma。

偏好设置新增“使用相机色彩显示 RAW 底片（仅影响查看）”，默认关闭。开启后采用有效的
相机原生 → 线性 sRGB 矩阵，再适配到工作空间；整图与局部放大使用同一变换。
非有限、退化、不合理或需要第四通道的矩阵不使用。底片采样与正片导出仍读取原生数据，
显示矩阵不保存为胶片标定参数。这项显示表征不能代替相机、胶片与光源的联合标定。

原生桥提供文件头、解包后和处理后电平的诊断：公共黑电平、通道偏置、重复黑电平模式、
白电平、通道线性上限、最大值调整阈值、亮部模式及警告。
LibRaw 已执行的扣黑不会再次执行。源量化间距按有效范围给出保守界限，并考虑处理后的
最大值调整；这改善标定精度信息，不重新改写像素。亮部处理仍保持原来的 clip 策略。
旧原生桥缺少扩展接口时明确报告不可用，使用原来的量化间距后备规则。

## 不需要色卡的原片审计

```powershell
dotnet run --project src/OpenRevelare.Cli -c Release -- audit-input `
  --input "D:/scans" --output "D:/reports/input-audit.json" `
  --repeat 5 --workers 1 --compare-full
```

输入可以是一个文件或一个文件夹，支持 RAW、TIFF 和两种 FFF 路由。只读原片，报告采用
临时文件加替换的方式保存，不能覆盖输入。默认顺序测量；`--workers 1..4` 允许测量吞吐，
仍按内存余量限制实际工作数。`--repeat 1..20` 记录逐次结果，不把第一次和热读取混为
一个“加速倍数”。操作系统磁盘缓存状态未强行控制，报告也不把第一次称为冷盘性能。

报告包含每次耗时、RAW 读取/打开/解包/处理/输出复制/缩小的阶段计时、缓存命中来源、
像素 SHA-256、每通道统计、文件色彩证据、黑白电平以及重复解码是否相同。
到达零或一的样本数量不是“已经损失的细节”判定，特别是浮点 TIFF 可以合法超出该范围。

`--compare-full` 增加低分辨率的全质量参考解码。RAW 比较半尺寸预览与全质量解码的通道
均值差异；输出网格尺寸相同且所有样本有限时也报告像素 RMSE。网格不同会省略 RMSE，
不会假装比较同一像素。TIFF 比较预览 CMM 与精确 CMM。它们都不是外部参考色差。
默认超过 32 MP 时跳过全质量参考，可用 `--max-full-mp 100` 显式提高预算。

对于未标记或 ICC 不可用的 TIFF，可用 `--tiff-assumption linear` 或 `srgb` 声明假设；
默认 `auto` 读取文件自身的证据。有效内嵌 ICC 始终优先。单个文件失败保留错误，其他文件
继续检查，最终退出码为 1；全部成功为 0，参数错误为 2，取消为 130。

日常界面不常驻展示解码器、电平、色彩管线、分析置信度与校正来源等技术信息。
【帮助 → 诊断】统一提供查看与复制，包含当前画面和显示链路报告；显示异常仍有简短提示。
偏好设置中的解码后端、FBDD、相机底片显示与并发数收在默认折叠的「高级解码选项」。
