# 135 自动裁切

在编辑器的「裁切」面板使用统一的「比例预设」下拉框，再点击「自动裁切本帧」或「自动裁切选中 / 整卷」。有勾选时仅处理勾选帧；未勾选时处理整卷。自动裁切覆盖目标帧已有裁切，可撤销，也可重新打开拖框工具微调。

自动裁切前不需要手动指定正片还是负片：检测器自己判断极性，并从反转和齿孔遮罩之前的线性预览识别。若某个画格实在无法可靠识别，只要还能测到两排齿孔，就会给出一个**推测框**（见下文），方便直接在此基础上拖框，而不是从零开始。

| 模式 | 目标 | 导出比例 |
|---|---|---|
| 135 全幅 — 内容 | 实际画面，向内留少量余量避开边界 | 横幅 3:2，竖幅 2:3 |
| 135 全幅 — 含边框 | 画面、上下齿孔和片边 | 横幅 37:35，竖幅 35:37 |

自动与手动裁切共用同一个下拉框。选择「自由」时，自动按 135 内容 (3:2) 检测；选其他非 135 比例时保留手动拖框操作，不会静默改成 3:2。正片、负片均从反转和齿孔遮罩之前的线性预览识别，不需要为了裁切改变反转参数。

## 识别和整卷稳定性

- 检测前通过 `FilmAutoCrop.Prepare` 统一应用当前帧的镜头畸变校正（`DistortionK1`）、90° 旋转/翻转与已有拉直角度，旋转空白角使用纯黑 `0` 填充，避免暗 RAW 中白角污染高分位齿孔阈值；内部盒式降采样上限提高至 `1200` 像素长边，使 GUI `1600` 预览保持原始像素级边界精度。
- 优先识别两排周期性齿孔，按标准横向排距 `28.17 mm` 与孔距 `4.75 mm` 分别估计横向与沿片像素尺度；在 log-RGB 空间比较画面与齿孔内侧片基肩部的曝光距离（匹配 `34.5–36.8 mm` 全幅画格并赋予 `36.1 mm` 标准片门温和先验），校验边框外侧齿孔排可见性，并根据高密度黑片基自动约束反转片极性；上下边界在对称与最小门高约束下微调至真实片门边缘。
- 齿孔排布提供小角度拉直信息，可靠时自动修正，裁切框位于拉直后的坐标中。自动修正限于约 ±5°，并遵守原有拉直控制的 ±15° 总上限。
- 同一处理范围内，按相同源尺寸、相同横竖方向及相同胶片极性（正片 / 负片分卷统计）分组，先剔除相对中位尺度偏离超过 8% 的离群项：内容模式在完整片门帧（`≥ 0.975 × 中位尺度`）的最小尺度上仅留 `0.8%`（`× 0.992`，每侧约 `0.14 mm`）光学安全内缩作为共享框大小；若个别暗场夜景帧的实际受光范围略窄于共享框，则在该帧检测范围内单独拟合紧贴的 `3:2` 框，既不漏出片基，也不连累整卷缩小。含齿孔模式仍使用可靠尺度中位数，逐帧只改变位置。
- 裁切大小使用 3×2 或 37×35 的整数倍，位置也落在源像素边界上，因此同组正常帧导出尺寸及宽高比完全一致，不受逐帧四舍五入影响。
- 含齿孔（带边框）模式按**两排齿孔给出的片中心**定位，而不是按画面片门中心：片门相对片中心可以有约 1 mm 的正常偏差，落在正片黑片基上就是上边框多出一条亮缝（负片片基同样是亮的，所以看不出来）。带边框的尺度同时被齿孔估出的 `35 mm` 片宽封顶，保证它不会因片门估大而超出片边；内容模式仍以画面为中心，不受这两条影响。
- 不能可靠识别、过曝片头（含光学渐变漏光片头）、双半格合并候选、片夹黑边伪边界、原片缺失或含边框区域超出输入范围时：该帧已有裁切就**原样保留**；若还没有裁切且两排齿孔仍可见，则按齿孔给出的片中心与像素尺度、加上沿片方向最强的一对曝光边界，放置一个 3:2（含边框模式为 37:35）的**推测框**，供直接拖框微调。推测框同时带回齿孔测出的**拉直角度**：先按该角度把画面转正，框落在转正后的坐标里，因此框与片边平行，不需要再手动拉直一次（若该角度加上已有拉直会超出 ±15° 上限，则不放置推测框，避免框落在控件范围之外）。推测框不会覆盖任何已有的手动裁切；状态栏会单独报出推测帧数，请逐张确认，不要把「推测」当成成功识别。
- 推测框只是起点：两排齿孔都不可见时（例如片边被裁掉）没有物理参照，不会凭猜测放框，仍保留原裁切。
- 所有检测完成后一次性应用；支持取消、撤销、重做和 `.ncproj` 保存。检测期间编辑参数或更换胶卷时不应用过期结果。

适用于一张翻拍照片包含一个完整 135 全幅画格的情况，可以含相邻部分画格。半格、XPan、没有完整画格的片头，以及同一扫描源已拆分出的多个虚拟画格，不属于该自动模式；仍使用现有手动预设 / 拖框裁切。夜景正片（如四周纯黑无画格边界的烟花）、过薄或半幅欠曝至片基的负片在画格边界与片基无法区分时会安全跳过。输入中已经缺失的齿孔或片边不会被补画。

## 本地启动

需要 .NET 8 SDK：

```bash
dotnet run --project src/OpenRevelare.Gui -c Release
```

## 验证

核心测试覆盖：横竖和翻转、正片 / 负片、倾斜齿孔拉直、低信息输入、尺度离群、缺失片边、混合分辨率以及像素级比例。工作流测试通过真实 TIFF 工程检查两种模式的整卷 / 选中帧应用、撤销重做、取消、工程保存和源文件 SHA-256 不变。

```bash
dotnet test src/OpenRevelare.Tests -c Release --filter 'FullyQualifiedName~FilmAutoCrop|FullyQualifiedName~CropAspectPreset|FullyQualifiedName~AutoCropWorkflow'
```

提供了独立的实拍检查工具（默认解码长边 `1600`，与 GUI `PreviewMaxEdge` 一致；支持 `--project=<工程.ncproj>` 复现已保存旋转/翻转/畸变及 `--preview-edge=<px>`），仅读取输入目录中的 RAW，生成逐帧裁切框预览、整卷概览和 `report.json`。绿色框为内容裁切，青色框为含齿孔裁切，黄色框为检测失败时的推测框；没有框的图需要人工检查。报告列出实际导出的像素尺寸、推测框及其比例，并检查比例没有漂移。

```bash
dotnet run --project benchmarks/OpenRevelare.AutoCropVerification -c Release -- <RAW目录> <独立输出目录> [--project=<工程.ncproj>] [--preview-edge=1600]
```

本次实拍验证使用复制到 `scratch/test-roll/RAW/` 的 28 张 C400 ARW（配合用户实际几何工程副本 `scratch/c400-manual-test.ncproj`，`27/28` 准确定位并导出统一 `3327×2218` 内容 / `3441×3255` 含齿孔尺寸，仅半幅欠曝无左边界的 `DSC01936` 安全跳过并给出推测框），以及 `scratch/test-slide/261101_Film 5294/` 中的 81 张 ARW（含反转正片与黑白负片，1600px 与 900px 均稳定定位全部 `74/81` 有效全幅画格：1600px 下正片正常帧统一 `3348×2232`、单张贴边剪裁暗场烟花 `DSC02030` 独立 `3255×2170`、黑白负片统一 `3393×2262`，准确跳过过曝片头 `DSC02015`/`02051`、纯黑夜空无边界烟花 `02033`/`02034`、全透片基 `02059` 及空白未曝光帧 `02088`/`02096`，这 7 张也各自得到一个 3:2 推测框供人工判断）。未改动桌面原件，也未将样片加入 Git。
