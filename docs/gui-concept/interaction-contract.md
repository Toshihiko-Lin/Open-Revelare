# 本轮先把这些交互做顺

基本架构沿用现有软件，不新增阶段导航、基准草稿、版本继承模型或交付计划系统。

## 可以先做的界面整理

- 检查器给当前帧身份；批量勾选数量单列。
- 按现有处理器计算目标数，给同步按钮动态范围文字。
- 片基／高光读数、采样动作和来源相邻。
- 卷级开关有稳定范围标记；主图下方渲染与文件导出视觉分隔。
- 工具提示可关闭，裁切提交／取消仍可见。
- 参数行的修改、复位、拖动和数字输入使用相同反馈方式。
- 成功反馈短，错误反馈持续并带恢复动作；保存状态独立。
- 保留现有键位，在输入文字或数值时避免误触全局动作。
- 增加或完善外部拖放的接收态与导入预检，区分新建卷／添加当前卷、图像／工程、重复／不支持材料；不能假定只改一个 AllowDrop 就覆盖原生预览区域。
- 在工具旁显示上下文键位，提供可收起的快捷键提示层；新增键位与现有菜单、平台键位和输入焦点一起检查。

## 需要修改实际行为的少数地方

重置拆分、偏好窗口所有退出方式的预览回滚、跨入口元数据字段保留，需要修改处理逻辑并验证。不能把这些说成只换布局就能完成。

批量范围本轮先解释现有行为，保留本帧／勾选粘贴／整卷应用的区别。未来若要统一回退规则，应单独讨论和验收，不随概念稿静默改变。

## 做成 Avalonia 原型时

沿用当前 Core、保存协调、批量事务、缓存和原生预览。项目目前固定 Avalonia 11.2.3；第三方 skill 的更新 API 示例只作参考，不借设计工作顺带升级依赖。

使用现有控件与编译绑定组合；真正需要自定义的是照片叠层、曲线和修复等专用交互。布局变化后重点检查 Windows 原生图像区域的覆盖与命中、macOS 菜单入口、中英文和 DPI。

## 怎么判断是否更好了

让用户在真实一卷照片上完成：检查片基 → 改一张曝光 → 复制到几个目标 → 裁切 → 导出。观察他在哪儿停住、猜测或回头找工具，再改那一处。

通过标准是执行前知道改谁、执行后知道发生了什么、出错后知道怎么继续。点击次数和视觉整齐仅作辅助；不凭一张截图判断完成。
