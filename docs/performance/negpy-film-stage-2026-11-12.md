# FilmBase 阶段复用：实现与配对实测

2026-11-12，NegPy 路线 M1 第二项实现。前一项规范场景转换优化见 [M0 组件记录](negpy-m0-2026-11-12.md)；完整阶段状态见 [实施记录](../negpy-optimization-progress.md)。

## 现在复用什么

前台预览将源域校正、除尘、密度反转和几何结果保存为不对外暴露像素的 `PreparedFilmFrame`。曝光、对比度、白平衡、黑白点、高光／暗部、饱和度和曲线变化时，只复制该中间图并完成输出映射与创作调整。完成结果不会反过来修改中间图。

缓存键包含 typed WorkingFrame 身份、原片版本、管线版本以及除已审查的 14 个创作字段外的全部可写参数。新增参数默认失效，不能因其放在成片页就自动忽略。片基、密度端点、黑白模式、矩阵、平场、镜头、除尘、裁切、方向、拉直和输出设置都会保守失效。LCC 仍以不可变加载快照身份计入，不为每个滑块事件遍历大平场。

原片与校准参考在读取前、准备后及结束后复核。使用已有 `SourceStamp` 元数据版本，保留其不识别“全部元数据原样保留的内容替换”的边界。中间结果不存入工程，不新增工程格式或迁移，不改变导出路径。

缓存最多两项、合计 **32 MiB**，优先服务当前正常／拖动预览；源对象只保留弱引用，避免额外锁住被逐出的 RAW 像素。可用内存不足 1 GiB 时清空并直接走原管线。换卷、清缓存与退出会退休当前代数，旧准备任务不得重新填入；取消也不保存未完成准备。邻帧预热继续使用原管线及原有完整结果缓存，不占用本缓存。

这是原有 96 MiB 完整准备缓存之外的一项额外预算；未宣称已经完成全应用的统一预算或 8 GiB 真机验收。

## 实验口径

与 M0 相同的 Windows／Ryzen 5600X／.NET 8.0.29 环境，Release、GPU Off、LibRaw、FBDD Off、ManagedV2；每种输入三个独立进程，每进程预热后交替 30 对曝光变化。两条路径使用同一解码和 CMM，包含相同暗角、拉直、裁切与填充。每对均核对处理像素与规范场景的原始字节、渲染身份相同。

render 指完整管线或实际 GUI 缓存调用（含参数键、查找和 finish copy）；prepare 再包含规范场景、直方图与 CPU fallback 编码。**不包含** RAW 解码、窗口、native bitmap、UI 发布、显示器或 NegPy。输入提前哈希，不是冷磁盘测试。

下文为三个进程各自分位数的中位数，不是合并样本分位数。原始 JSON 保留全部计时、跨线程托管分配及程序集／CMM 身份。

## 测量结果

1200×800 合成图：

- render P50：31.95 → 15.60 ms（减少 51.2%）；P95：68.35 → 19.34 ms。
- prepare P50：87.40 → 68.37 ms（减少 21.8%）；P95：112.43 → 75.51 ms。
- 每次 prepare 的托管分配中位约 107.10 → 37.48 MB；保留的 FilmBase 中间图为 11,027,328 字节。

约 101.74 MP 的真实 RAF，预览 1456×1092：

- render P50：43.17 → 20.20 ms（减少 53.2%）；P95：70.18 → 25.39 ms。
- prepare P50：132.71 → 109.63 ms（减少 17.4%）；P95：161.01 → 119.50 ms。
- 每次 prepare 的托管分配中位约 177.18 → 61.91 MB；保留的 FilmBase 中间图为 18,246,384 字节。
- 原片 SHA-256 与 M0 相同，三次运行前后均未变化；未写原片、未创建工程。

每个进程的缓存均只准备一次，随后 30 次曝光变化命中；所有对照逐字节一致。分配降低不等于同等降低峰值 RAM：缓存增加了常驻图像，native CMM／解码缓存不包含在托管分配数里。首次 miss 仍需准备并为 finish 复制图像，本实验主要说明连续创作编辑的收益，不能推广为首次打开也快 17%–22%。

## 验证与剩余工作

新增 15 个自动用例覆盖 LegacyV1／ManagedV2、黑白、SDR／HDR／线性输出、印片 LUT、扩展参数、几何填充、14 类创作复用、25 类参数失效、源身份／版本、字节和条目预算、参考变化、低内存、取消、代数退休与前台实际准备入口。

Release `-warnaserror` 完整测试 **1,614 通过、10 项硬件跳过、0 失败**（主测试 1,549，Win32 40，macOS 契约 25）。这些是自动测试，不替代真实桌面、低内存与跨平台硬件验收。

桌面诊断可设 `OPENREVELARE_FILM_CACHE=0` 关闭前台复用，以相同卷和操作对照；默认开启。`preview.film.hit/miss/bypass` 进入已有诊断计数。下一步优先推进参数分组重置／修改反馈和实际桌面取证；M0 双软件对照仍未完成。

## 收敛补测：强制未命中成本

按“控制改动、先验证已有收益”的取舍，未增加产品模块；只扩展原基准，补充校准变化时的缓存成本。v2 基准每个进程先做 30 对连续曝光，再做 30 对黑端变化；后一阶段每对前清空缓存（清空不计时），核对 30 次准备、0 次命中。两阶段每对均检查渲染字节、规范场景字节及指纹相同。

合成图与同一 RAF 各运行三个独立进程，按顺序执行，不与测试或其他基准并行。下表仍是三个进程各自分位数的中位数，单位 ms，不是合并分位数。算法、GPU Off、几何／暗角／齿孔负载沿用上文；解码、CMM 与 JIT 均已热，强制未命中不等于冷启动。

| 输入与阶段 | render P50 完整→缓存 | prepare P50 完整→缓存 | prepare P95 完整→缓存 |
|---|---:|---:|---:|
| 合成，连续曝光 | 34.03→16.43 | 87.42→68.81 | 101.68→76.74 |
| 合成，强制未命中 | 32.47→34.14 | 87.78→88.87 | 108.09→100.08 |
| RAF，连续曝光 | 45.88→20.74 | 130.75→104.71 | 167.08→115.21 |
| RAF，强制未命中 | 46.11→47.12 | 130.00→130.82 | 148.39→145.97 |

未命中的托管分配中位数：合成 107.10→117.29 MB，RAF 177.18→194.03 MB，约增加 9.5%。这是首次保留准备图、为成片阶段复制图像的代价；连续曝光仍为 107.10→37.48 MB、177.18→61.91 MB。分配不是常驻内存或包含 native 的总内存，不能由此声称峰值 RAM 同比例变化。

本负载中，未命中 prepare P50 的额外成本约 1.09／0.82 ms，连续曝光节省约 18.61／26.04 ms。保留当前缓存实现，不为这个量级的成本再扩展渲染架构。P95 有进程／GC 波动，未命中 P95 较低不证明首次准备更快；结论也不覆盖解码、原生 UI 发布、任意校准任务或 NegPy 对照。

六次进程均通过逐对一致性；三次 RAF 原片前后完整 SHA-256 均与上文一致。原始数据：[合成 1](negpy-film-stage-2026-11-12/miss-generated-1.json)、[2](negpy-film-stage-2026-11-12/miss-generated-2.json)、[3](negpy-film-stage-2026-11-12/miss-generated-3.json)；[RAF 1](negpy-film-stage-2026-11-12/miss-raf-1.json)、[2](negpy-film-stage-2026-11-12/miss-raf-2.json)、[3](negpy-film-stage-2026-11-12/miss-raf-3.json)。
