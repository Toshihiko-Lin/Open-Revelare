# NegPy 对标研判与 OpenRevelare 优化路线

> 2026-11-12 范围修订：本文是竞品学习清单，优先级不代表实施承诺。用户要求精简后，已撤回命名版本、指定基准 A/B、可见及持久化历史、参数查找、分组重置与调整计数；取消场景组，不实施持续继承等额外模块。保留性能优化、原有单一重置的安全修复、批量结果和窄窗修复。Goal 保持暂停；当前状态以 [实施记录](../negpy-optimization-progress.md) 为准。

研究日期：2026-11-12。性质：源码、文档与界面材料审查；本轮不修改产品实现。

后续实施已于同日启动，当前状态及实际证据见 [实施记录](../negpy-optimization-progress.md)。下文为研究时制定的路线，不代表全部能力已实现或验收。

## 判断与建议

**应把 NegPy 作为工作流完整度、交互反馈和渲染架构的重点对标对象。下一阶段应优先投入“更快得到可用的第一张、更容易完成一卷、更放心比较与修改”，随后补齐局部修片和输出预检。**

NegPy 的优势不只是多几个滑块：它把底片处理、印相、测量、局部编辑、版本比较、批量管理和采集组织成一个暗房。OpenRevelare 已有可解释校准、色彩语义、HDR、整卷工程、可靠归档及 PURENeg 除尘基础。更合理的策略是保留这些基础，把它们转化为更直接的成片体验。

不能由本次材料认定 NegPy 在所有画质、速度、色彩准确性上全面领先。尚未在同机、同原片、同尺寸、同输出条件下做双软件实测；也没有现场完成双方全流程操作。以下对性能的判断是架构潜力，对 UI 的判断是材料与代码支持的设计判断，不是用户研究结果。

## 一、五个维度的研判

### 1. 功能完整度：从“反转器”扩展为“完成照片的暗房”

NegPy 覆盖彩负、黑白、正片、局部加减光、版本历史、扫描与联机采集，形成较完整的流程。我们的整卷物理校准与归档能力已有基础，主要短板是创作工具、版本比较和跨任务衔接。不要把已存在的批量导出、虚拟副本、自动裁切、波形图、平场、镜头校正重复立项。[功能概览 S1](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/README.md)

### 2. 性能速度：核心在数据流和失效范围

NegPy GPU 引擎保留中间纹理，检查最早失效阶段；改后期参数可复用上游结果，纹理池和持久 staging 减少分配。分块导出先统一全局统计，再处理带邻域的 tile，并交错提交和回读。它具备低显存路径，但仍分配全尺寸 CPU 结果缓冲，不能称为全链路常量内存。[GPU 引擎 S2](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/services/rendering/gpu_engine.py)

我们已采用后台交互渲染、低分辨率拖动、最后参数合并、邻帧准备和有预算缓存。`Stage2` 已融合逐像素循环；这些不是待补的空白。当前 GPU 是缩放、锐化、LUT 等算子加速，并非密度反转到显示的完整常驻链。下一步应先量出 RAW 解码、规范场景转换、复制、CMM 和发布各自成本，再选择 GPU 改造范围。

### 3. 交互：把用户意图变成可见、可比较、可恢复的操作

NegPy 值得学习的是统一控件行为、修改状态传播、参数搜索、命名版本、历史比较和方案选择。我们有撤销与虚拟副本，但“能回退”距离“知道改了什么、可以放心试”还有体验差距。[历史实现 S3](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/desktop/view/sidebar/history.py)、[搜索实现 S4](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/desktop/view/widgets/command_palette.py)

### 4. 原理：学习印相建模与自动化的约束，不混淆物理恢复和风格

双方都使用对数域，但并非同一种映射。NegPy 有分通道归一化、中性轴测量、自动印相密度与反差，以及趾部、直线段、肩部和纸张响应。我们应保留 FilmBase / SceneBase 的分工，在创作层增加可解释的印相模型，并将自动推断与实测参数分别标记。[归一化 S5](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/features/exposure/normalization.py)、[原理 S6](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/docs/PIPELINE.md)

### 5. UI：优势在层级和工作密度，不能只复制深色主题

官方截图呈现大画布、连续胶片栏、集中检查器、分析图表和一致的参数卡。视觉学习应落实为画面空间、对齐、分组、状态反馈和可发现性。截图是宽屏状态，无法证明窄屏、辅助技术和多 DPI 同样优秀。我们已有浅深主题、固定标签与同步范围改进，应延续现有视觉语言，优先收敛重复入口和状态散落。[官方截图 S7](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/docs/media/0680.webp)

## 二、72 个值得学习的点

以下是学习与改造清单，包含已有能力的深化；不表示 NegPy 的每一项均已由本轮运行验证，也不表示本项目完全没有相应基础。优先级结合本项目收益与依赖确定。

### A. 首张与整卷流程（01–10）

01. **快速默认成片，P0。** 导入后优先显示可用正片，后台逐步完善统计；保留高级校准入口。验收看首次可编辑时间，而非进度条先出现。
02. **明确素材模式，P1。** 彩负、黑白、正片分别组织默认参数与可用控件；E-6 是独立验证的输入路径，不是关闭反转即可宣称支持。
03. **场景分组，不采纳。** 记录对标软件按光线分组共用创作基线的做法。按用户 2026-11-12 的取舍，本软件沿用勾选帧同步和虚拟副本，不引入场景组、成员管理或自动分组。
04. **自动估计与锁定分离，P0。** 看得出哪些来自自动分析、整卷值或本帧覆盖；用户锁定值不能被后台刷新覆盖。
05. **可恢复的参考缺失状态，P0。** 延续依赖恢复能力，让错误直接带到恢复入口；不增加第二套资源管理系统。
06. **保留／拒绝筛片，P1。** 用明确标记替代复用批量勾选；拒绝帧是否导出由导出界面明确说明。
07. **跨卷虚拟集合，P2。** 为精选和项目交付建立集合，引用原工程；先解决同一帧多处编辑的所有权。
08. **批量结果形成闭环，P0。** 复用已有逐帧任务记录，提供失败定位、查看输出和安全重试；不重复建设队列。
09. **偏好继承可解释，P1。** 哪些参数延续到下一帧应可见且稳定；不能将上一帧临时曝光悄悄带入整卷。
10. **元数据模板，P2。** 胶卷、相机、镜头、冲洗流程可复用；导出前继续保留隐私选择。

借鉴来源：[工作流指南 S8](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/docs/USER_GUIDE.md)。其中“作用域可见、覆盖可恢复”比照搬全部面板更重要。

### B. 性能与资源（11–22）

11. **阶段级失效，P0。** 将解码、预处理、FilmBase、创作、显示准备分别建立版本键。先完成 CPU FilmBase 结果复用，再决定 GPU 后端范围。
12. **数据常驻，P1。** GPU 实验应连续执行相邻阶段，计入上传、回读和显示桥接；不能只报告 shader 时间。
13. **显示转换作为独立热点，P0。** 排查规范场景转换、复制和显示 CMM；根据契约复用转换，不能用跳过色彩管理换速度。
14. **共享解码与低拷贝，P0。** 延续原片字节缓存、解码合并和虚拟副本共享；为全尺寸缓冲明确唯一所有者与生命周期。
15. **预览专用 RAW 路径，P0。** 在解码器允许且画质可验证时使用缩略／半尺寸解码；相机 JPEG 只可作加载占位，不能用于定色或最终校准。
16. **按内存准入预取，P0。** 学习同时估算常驻和临时内存，并为核显共享内存留余量；我们的邻帧预热策略已有，应改预算而非重建。
17. **导航意图驱动预取，P1。** 连续前进时提高前向优先级，快速跳转及时取消；预取不能阻塞前台 RAW 解码。
18. **按交互预算选择分辨率，P1。** 当前固定降采样可演进为预算策略；拖动清晰度与释放收敛必须分别量化。
19. **分块导出与统一统计，P1。** 测光和自动参数先冻结，各 tile 共享；邻域算子带足 halo，避免亮度变化与接缝。
20. **纹理／缓冲池，P1。** 按尺寸和用途复用，变更尺寸及时清理；低显存采用更小 tile、减少在途缓冲。
21. **后台分析降频，P0。** 直方图、波形等不必随每次指针事件全量计算；显示统计对应的图像修订必须一致。
22. **后端故障可恢复，P1。** 保留现有 GPU 收益判断与 CPU 回退；新后端要覆盖 device lost、驱动失败、显存不足和导出中断。

依据：[GPU S2](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/services/rendering/gpu_engine.py)、[缓存 S9](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/services/rendering/preview_cache.py)、[预取预算 S10](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/services/rendering/prefetch_policy.py)、[RAW 路径 S11](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/infrastructure/loaders/rawpy_loader.py)。这组学习指向资源组织，不支持预先承诺速度倍数。

### C. 控件、操作与恢复（23–34）

23. **统一数值控件，P0。** 数字直输、精细调整、重置、单位与范围使用同一行为；复查已有控件后补差。
24. **重置安全，P0。** 保留原有单一重置入口，避免误清校准、裁切和扫描分格；分组重置已撤回。
25. **修改标记向上汇总，不采纳。** 记录竞品做法；本软件撤回额外标记和页签计数，保持原参数面板。
26. **明确批量范围，P0。** 延续共享目标解析，操作前显示“应用到其他 N 帧”；复制选择与真实写入范围一致。
27. **作用范围可见，P1。** 借鉴其范围表达，明确当前帧、勾选帧与整卷的同步目标，并提供撤销。持续继承与覆盖层暂缓，不为此新增数据模型。
28. **语义命令搜索，不采纳。** 用户明确不需要参数查找，相关实现已移除。
29. **快捷键帮助与冲突检查，P1。** 先做当前快捷键总览，再开放重映射；区分文本输入焦点与全局动作。
30. **画布临时反馈，P1。** 键盘调整隐藏面板时也能读到参数与新值；短时提示不能遮挡采样位置。
31. **命名版本，不采纳。** 现有虚拟副本已可保留方案，撤回额外命名管理及工程格式扩展。
32. **历史可视与重启恢复，不采纳。** 保留原有会话撤销／重做，撤回历史窗口与持久化。
33. **指定基准比较，不采纳。** 撤回新增 A/B 下拉、快捷键及状态，保留原有预览比较。
34. **方案优选，不采纳。** 不增加多候选窗口或逐轮选择流程。

### D. 成像原理与质量（35–46）

35. **无片边的快速估计，P1。** 借鉴内容统计归一化作为快速起点；标记“估计”，有可信片基时允许切换到物理校准。
36. **中性轴分段诊断，P1。** 高光、中间调、暗部的色偏分别可见；低置信度时建议复查，不强制中性化有色光源。
37. **自动亮度与反差解耦，P0。** 曝光目标和动态范围目标独立调节；不能靠一个自动按钮同时漂移多组用户参数。
38. **冻结自动统计，P0。** 同一参数快照的预览与导出使用相同分析区域和测量；不随分辨率重新选黑白点。
39. **测量 ROI 与边界遮挡分离，P0。** 排除片夹、齿孔、灯板；有用户分析区域时明确优先级。
40. **参数化印相曲线，P1。** 在创作层提供趾部、肩部和枢轴；保留现有 Cineon 和 LUT 结果，不静默迁移旧工程。
41. **可追溯纸张配置，P2。** 资料来源、拟合方式、观测条件和版本随配置保存；名称相同不等于真实暗房完全一致。
42. **高光与暗部保护，P1。** 自动映射应限制过冲、保持单调；雪景、夜景和高调照片不可机械拉满黑白。
43. **分清串扰修正与风格饱和度，P0。** 本项目已有 `C41Crosstalk` 和 Path A，继续各司其职；纸张染料分离属于创作，不回写物理校准。
44. **饱和度保护中性与高彩度，P2。** 借鉴染料分离与阻尼思路，先建立饱和色测试，防止鲜艳色块失真。
45. **扫描裁切与输出裁切分开，P1。** 提示源通道已饱和与显示／导出白点裁切的不同修复方式。
46. **预览与导出语义一致，P0。** 来源白点、输入 ICC、线性状态、输出配置与管线版本进入缓存身份；延续本项目的显式色彩合同。

依据：[归一化 S5](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/negpy/features/exposure/normalization.py)、[原理 S6](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/docs/PIPELINE.md)。上述优先级与边界是针对本项目提出的方案。

### E. 局部修片与测量工具（47–56）

47. **局部加减光，P1。** 优先实现椭圆、渐变和画笔曝光；操作在正确的创作域进行，不能用叠加屏幕颜色模拟。
48. **蒙版统一坐标，P1。** 复用 PURENeg 的源域坐标经验；旋转、裁切、镜头校正、区域放大与导出必须一致。
49. **局部参数逐步扩展，P2。** 曝光稳定后再增加局部反差与色彩；首版不复制全局所有控件。
50. **蒙版列表与显隐，P1。** 选中、启用、命名、羽化和反转可发现；逐笔撤销与整组取消边界清楚。
51. **除尘细分工具，P1。** 在既有 PURENeg 检测、补画、恢复上补长划痕与克隆策略；先统计失败样本，避免重做已有能力。
52. **红外除尘作为独立输入，P2。** 先验证真实 IR 样片、RGB 对齐和不适用乳剂，不能把 RGB 模型输出称为红外检测。
53. **试条与变体网格，P1。** 同一画面显示不同曝光／色温候选；所有候选共享缩放、裁切和显示条件。

## 三、需要明确保留的技术边界

### 不将内容推断等同于物理片基

NegPy 的内容统计降低了片边取样门槛，但画面偏色可能来自光源、主体、衰退或成像链。对雪景、舞台灯、海水、单色背景，强制中性会改变作者意图。建议保留“可信参考校准”和“快速自动估计”两种入口，记录方法、置信度、ROI 与版本，允许锁定与回退。不要把估计结果包装成测量事实。

### 不直接复制默认色彩空间假设

NegPy 文档明确说明原生线性 RGB 及 Adobe RGB 边界假设。它适合其处理体系，但不能证明任意相机通道天然就是 Adobe RGB。OpenRevelare 已有输入解释、ACEScg、ManagedV2 和输出语义，不能为了迁移算法跳过这些边界。移植曲线、测光或局部算子时，应说明输入／输出域，并以真实样片验证。[S6 原理](https://github.com/marcinz606/NegPy/blob/d8123a9b2a18fdaab5941347a91e402fa936d3dc/docs/PIPELINE.md)

### GPU 是投资选项，不是预设答案

本项目旧组件基准中，规范场景转换 P50 约 135.7 ms，像素管线约 16.6 ms；两张 80.6 MP ORF 的旧 CLI 局部基线 RAW 加载约 31 s，热态渲染约 1.25–1.32 s。这些数据都来自 2026-10 的特定样本，不能代表当前版本或双方快慢，但提示先重跑分段测量。若瓶颈是解码或场景准备，仅迁移反转到 GPU 不会解决主要等待。[本地性能记录](../performance/preview-diagnostics.md)

### 历史、软打样、采集必须有各自的数据合同

命名版本应冻结参数和依赖身份；比较时使用一致视图。打印软打样是显示变换，不能污染导出母版。采集是可能失败的长任务，必须有设备恢复与文件完整性边界。不得为了表面功能对齐引入无法恢复的半成品状态。

### 复用代码前逐项查资产来源

双方仓库以 GPL-3.0 为主，但纸张曲线、ICC、第三方数据、模型和截图可能有各自条款。实现时优先复用公开原理并独立实现；实际复用代码或数据需保留对应来源、许可与署名。此项是接入资产的工程检查，不是本次计划的阻塞项。

## 四、执行路线：先验证，再按里程碑推进

以下保留原阶段划分供研究追溯。范围收缩后原 12–17 人周估算作废，不作为当前排期；Goal 已暂停，不自动启动后续阶段。

- 固定双方版本、机器、GPU／驱动、后端、原片、缓存状态、窗口与输出设置。执行下节矩阵；形成原始 JSON、计时记录和样片索引。

### M2：比较与整卷一致性（原方案，已撤回，不再实施）

### 独立技术分支：常驻 GPU 原型（先 3–5 天决策实验）

## 五、性能与质量验收协议

### 样本与场景

至少建立：24 MP Bayer RAW、45–60 MP RAW、已有 80.6 MP ORF、16-bit TIFF、黑白负片、裁去片边彩负；另加夜景、雪景、舞台光、肤色、饱和花卉与划痕。新增 E-6／IR 能力时补相应真实输入。每类至少 3 张，整卷任务至少一卷 36 帧；样本要获得使用许可并保存内容哈希。

双方关闭非必要效果后比较等效基础工作负载，再分别评估完整效果。相同尺寸、位深、质量与色彩目标；无法对齐的印相模型只比较各自耗时与输出性质，不声称画质等价。单列 PURENeg／其他除尘成本。

每种配置至少 3 次独立进程启动；交互每场景至少 30 次事件，保留 P50/P95、样本数和原始记录。OS 磁盘缓存不可控时标为“首次进程／热文件”，不能冒称冷磁盘。记录解码、预处理、校准、创作、显示变换、UI 发布、写出、峰值 RAM／VRAM；并发嵌套阶段不可直接相加。

### 建议目标，而非已有成绩

- 输入反馈：P95 ≤ 50 ms；指控件响应和工具反馈，单独统计图像更新时间。
- 拖动预览：24 MP 输入、长边 1600 的编辑预览，P95 图像更新 ≤ 100 ms；长操作保持可取消，不累积旧任务。
- 热态切帧：已准备帧 P95 首次发布 ≤ 150 ms，且无过期图像；首版可先设 ≤ 250 ms，依据 M0 分档确认。
- 释放收敛：常规预览 P95 ≤ 300 ms；100% 区域细节另立指标，不混用预览与全尺寸。
- 首张与大 RAW：先以 M0 为基线，针对最大等待阶段提出 ≥ 30% 的改善目标；是否能实现取决于瓶颈。占位显示不计为可编辑正片。
- 内存：并发解码、准备缓存、全尺寸槽、模型、导出统一预算；在 8 GiB 机器执行一卷任务无 OOM，且预取可主动退出。不能把图像库或模型占用排除后宣称达标。
- 导出：在无色彩或像素退化的条件下，选定负载吞吐较基线提升 ≥ 20%；达不到时说明限制，不能降质量凑指标。

显示发布时间与屏幕上实际变化不是同一测量。内部日志用于分段；真实交互延迟以 UI 自动化或同步录屏／输入时间戳补足。上述阈值在 M0 后按机器档位冻结，再作为发布门槛。

### 画质与正确性

- 点运算：优先严格误差测试；几何插值、局部滤波与纸张 LUT 分开规定容差。
- 有标准目标的路径可用色差与灰阶误差；创作映射用盲评、裁切率、单调性及曝光连续性，不能用单一 ΔE 排所有风格。
- 对照 CPU/GPU、缓存／重算、预览／导出、区域／整图、分块／整图；同一冻结统计和依赖版本。
- 覆盖快速切帧、拖动中换卷、取消后新任务、参考变更、低内存、显存丢失和旧工程重开。
