# 相机 CFA 与 dark/open 首版实现

日期：2026-11-18。接续 [双流程设计](camera-scanner-calibration-redesign.md)。状态：实现 Windows 原生桥、Core 测量与 GUI 试算入口；未接入胶卷反转，未输出解马赛克 RGB，也未完成真实设备参考验证。

## 数据路径

`CameraCaptureCalibration.ReadRaw` 使用独立 LibRaw 上下文打开文件，只调用 unpack，随后复制原始活动区域的整数 Bayer 采样。`or_raw_mosaic_v1` 返回平面指针与扁平元数据，托管侧在上下文释放前按原生行跨度复制；LibRaw C++ 结构体不跨 ABI。

返回的活动区域保持未旋转的传感器坐标，并携带完整传感器尺寸、左上偏移、2×2 CFA 通道、方向、机身标识／可用序列号、ISO、曝光、白电平、可用光圈与焦距、解码构建标识和用户声明的会话 ID。活动区域不等于既有显示 inset crop。

不调用 dcraw_process，因此不经过其扣黑、UniWB、亮度缩放、u16 RGB 输出、FBDD 或解马赛克。LibRaw unpack 内部仍可能有格式相关解包／解释，不能宣称这些采样就是文件压缩字节或完全未经解码器处理。

首版拒绝 X-Trans、非 2×2 RGB Bayer、浮点／多通道线性 RAW 及特殊旋转传感器布局。旧 native bridge 缺少新入口时明确报错，普通解码路径不受影响。Windows 已重建；其他平台需从本次源码重建并验证，不能使用旧二进制执行试算。

## 测量与参考匹配

`Measure` 直接计算 `(sample-dark)/(open-dark)`，没有第二次减元数据黑电平，也没有图像内容端点归一化。要求设备标识、序列号可用值、原始几何、CFA 相位、方向、解码构建及会话 ID 一致；ISO、曝光、白电平、光圈与焦距记录严格匹配。缺少 ISO／曝光证据时允许原始读取，但拒绝计算。光圈／焦距为 0 代表上游未提供，不能据相等的未知值宣称实测相容。

会话 ID 是用户对同一设备／镜头／光源／几何的声明，不是光源 SPD 或硬件稳定性测量；两份文件的手填相同设置不足以验证物理一致。首版不从配置文本补填缺失的 EXIF，也不推断跨曝光换算。

对样本／参考达到声明白电平、无效分母、负透射和零透射分别标记，不用 epsilon 制造有限密度。不可用测量输出 NaN，原始采样仍由独立输入对象保留。高于 open 的正值保留并标记，不强制钳位到 1；这些数值需后续独立参考解释。白电平检测当前基于 unpack 后声明的公共上限，不声称已覆盖所有设备的通道饱和或坏点规律。

仅比 dark 高一个整数码值的正信号仍计算透射率，不设通用近黑排除阈值；“可计算”不代表精度足够。当前不提供噪声／不确定度估计、坏点地图或光谱通道表征。

## 用户试算

设备校准窗口选择相机、传感器原始采样、设备相对透射率目标；登记一张 dark、一张 open，再点击“测量相机样本…”。试算前后核验这两份登记参考的摘要，独立读取三份文件并检查相容性。GUI 报告采样尺寸、可计算数量及高于 open 数量；不把该摘要标为校准通过，不保存已验证能力，不将结果应用到胶卷。

多张参考的平均／稳健合成尚未实现，存在多张同角色参考时要求用户明确选择，不随意取第一张。试算有剩余内存检查；无可计算采样时仍返回带原因标记的结果，不当作有效模型。

## 验证范围

合成 DNG 独立写入非零黑电平及非单位 as-shot 白平衡，逐采样核对 unpack 后计数，证明新读取路径没有执行既有 RGB 后处理。单元测试覆盖已知透射率、非零偏置、近暗场一码、高于 open、饱和／无效分母／非正测量、条件失配、CFA 相位、格式拒绝及源文件不改写。

相关原生解码、整数转换、预览缩小与输入审计回归应与新测试共同运行。合成数学与解码回归不能代替真实 dark/open、设备线性、杂散光或密度精度验收。下一阶段应增加独立采集参考、可保存测量报告与引用摘要、校正结果的明确解马赛克策略，再接入配置失效及卷级参数重建。

本机验证：Windows native bridge 重建成功；首轮采集／原生解码／缩小／转换／审计测试 38 项通过，最后一轮采集／配置／原生解码／审计测试 29 项通过（集合重叠，不相加）。真实 `PFCS025.raf` 只读冒烟取得 11662×8746 活动区域、11808×8754 原始传感器布局及 `0,1,3,2` 相位，101995852 个采样，读取前后文件 SHA-256 一致。该实拍检查只证明这份文件可读取，没有真实配对 dark/open，因而不构成设备校准验证。
