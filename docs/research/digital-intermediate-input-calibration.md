# 数字中间片方向与输入设备颜色标定

日期：2026-10-11。产品方向由用户明确；下面的实验顺序是实施准备，具体标定模型尚未获得测量验证。

## 已确定的边界

OpenRevelare 以数字中间片为思路，当前目标是颜色准确性。链路为输入测量与标定、负片密度及端点校准、标准中间表示、LUT 外观和输出转换。每一步的数值域与所有权必须明确。

- 不增加相纸渲染分支、相纸号数或数字暗房式相纸工作流。
- 保留现有 Cineon 输入 LUT 路径及输出契约。LUT 可以表达印片外观，但外观不能承担设备标定。
- 输入标定、密度校正、片基/端点和 LUT 分开记录；调节外观不能改写标定。
- 密度校正必须记录来源、测量域和适用条件；相机 RGB 密度不得未经验证就声明为 Status M。
- UI 按用户目的组织，普通入口展示标定状态、负片校准、外观与输出；专业矩阵置于详细设置。
- 既有方向处理、齿孔开关和独立同步的布局要求继续有效。

这些边界细化 [色彩管理架构](../color-management-architecture.md) 的输入政策，不替换其工作空间、显示管理、LUT 契约和旧工程策略。

补充参考：[NexFilm 硬件校准核查](nexfilm-hardware-calibration-reference.md)。其 dark/open 实际计算、质量掩码、独立拟合验证及分级失效设计可供借鉴；真实硬件验证和标准密度能力仍未完成。采用这些设计不意味着改变本项目的工作空间或数字中间片路径。

## 当前缺口

`RawDecode.AdmitRawWorking` 正确记录了相机原生、未标定的输入及兼容透传状态；这是一种诚实的来源记录，不是已完成的设备表征。

`InputTransform` 已提供输入基色到工作空间的变换接口，`Decouple` 提供线性与密度域校正，`DensityEndpoints` 约束反相两端。需要验证这些变换如何与真实测量共同求解，不能只插入普通相机 ColorMatrix 后将来源状态改成已标定。

## 下一步的实验顺序

### 1. 固定测量条件和参考目标

记录相机/扫描仪、灯板及工作模式、曝光、ISO、镜头/光圈、解码器版本、黑电平、白平衡和线性处理。需要检查重复测量、通道截断、空间不均匀及曝光比例关系；不预设所有缺陷都能由一个颜色矩阵解决。

明确标定目标：设备透射测量的一致性、标准密度量的近似，和经胶片反相后的场景颜色准确性是不同目标。后一目标涉及胶片曝光/冲洗，不能仅用设备自身的中性参考推导。哪些量可由现有样本辨识，哪些需要额外参考，先写清再拟合。

参考应尽量不包含印相纸、创作 LUT 或未知扫描软件调色。已有带 Endura 相纸链路的数据可用于受限研究，但不能当作纯设备标定真值。

### 2. 比较有约束的候选模型

先建立当前未标定路径的基线，再比较有测量支持的线性校正、密度域校正，以及必要的联合方案。不预先决定一定采用某个 3×3 矩阵，也不假定解出“输入基色”就获得了通用相机 profile。

拟合需要消除输入增益、片基和端点之间可以互相补偿的自由度，锁定参考尺度。候选变换应与 `TBase`、端点及已有去耦在同一数值域内求解/重算。

对负值、接近零值和当前保护性混合的触发情况单独统计：保护函数会改变实际变换，不能只验证理想矩阵。数据不足时维持未标定状态。

### 3. 在独立数据上验证

使用留出色块、不同曝光和重复拍摄；能取得其他胶片或设备样本时，再测试外推范围。训练色块误差下降不能单独作为成功证据。

关闭艺术 LUT、AI 和创作编辑，在统一参考白点与参考域下比较：中性轴、色相/色度误差、亮度误差、极端色块、跨曝光稳定性及数值异常。色差指标必须附带其参考和观察条件，验收阈值在看到拟合结果前确定。

### 4. 将通过验证的结果作为标定资产接入

资产至少包含：设备与光源标识、解码配置、适用胶片/工艺范围、参考数据来源及哈希、处理域与顺序、模型参数、片基/端点依赖、拟合方法与版本、验证结果和资产身份。

设备或输入处理改变时，检测适用条件是否失效；不能静默继续宣称已标定。输入标定变更会使依赖它的片基、端点、去耦、预览和导出缓存需要重建。旧工程保持明确的版本路由。

UI 首先回答“这套标定是否适用于当前输入、验证到什么范围”；不要求普通用户手填九个矩阵元素。

## 本阶段产物

先交付测量协议、参考数据清单、可复算的拟合与留出验证，再确定产品中的标定模型和接入方案。没有设备及参考样本的实测结果时，不生成虚构的标定参数，也不把通用预设包装成颜色准确性已完成。
